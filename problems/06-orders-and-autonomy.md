# Problem 06 — 角色命令与自主行动的共同接口

## 目标

让每个角色都能接受外部命令，也能在没有命令时自主决策，同时保持统一的角色类型和模拟规则。

## 问题

区分持续性的 `Order` 与单个模拟步的 `Intent`。例如，`GoTo position` 是持续命令；每个 tick 中产生的 `MoveTo position` 是当步意图。

实现按 ID 设置或清除角色命令，并提供类似如下的决策函数：

```haskell
decideActor :: WorldView -> Actor -> Intent
```

有命令时由命令产生意图；没有命令时由自主策略产生意图。本题的最小自主策略可以只是等待，但两种来源必须汇入相同的 `Intent` 类型。

## 约束

- 玩家身份不是特殊 `Actor` 类型；控制权是对任意 `ActorId` 发出的命令。
- 修改一个角色命令不影响其他角色。
- 对不存在 ID 的命令返回明确错误。
- 命令处理和角色决策不直接移动角色；移动仍由模拟步骤计算。

## 验收场景

- 给角色 A 设置前往目标的命令后，A 的决策结果是对应移动意图。
- 清除命令后，A 使用自主策略。
- 给 A 发命令不会改变 B 的命令或状态。
- 对无效 ID 设置或清除命令会得到明确错误。
- 两个角色都使用同一种 `Actor` 和 `Intent` 类型，不因一个受玩家控制而分叉模拟代码。

## 思考

为什么“长期命令”“当步意图”和“最终位置”是三个不同的概念？把它们合成一个 `targetPosition` 字段会让哪些情况难表达？

## 可选拓展

增加“命令完成条件”：角色进入目标半径后自动清除命令；将判定放在负责命令进度的模块中。
