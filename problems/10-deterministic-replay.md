# Problem 10 — 固定步长、命令记录与确定性回放

## 目标

把此前的地形、角色决策、移动和冲突规则组合为可重复运行的全局模拟，并能重放一次运行。

## 问题

定义一个固定模拟步长，并记录按 tick 排序的外部命令。给定同一种子、相同初始配置和相同命令序列，从头运行两次后应得到相同世界状态。再实现回放：从相同初始状态重新应用记录的命令，复现原结果。

概念接口可以是：

```haskell
runTicks :: Int -> [CommandAtTick] -> World -> World
replay   :: InitialConfig -> [CommandAtTick] -> World
```

模拟时间只能由固定步长推进；渲染或终端输入等外部时间不得直接改变单步模拟时长。

## 约束

- 随机性必须来自明确的种子或世界状态，不在规则函数中偷偷读取系统随机数。
- 同一 tick 的多个命令有明确、稳定的应用顺序。
- 决策、候选冲突配对和结果提交都不能依赖不稳定的容器遍历顺序。
- 每步后检查身份唯一、位置有限（不是 NaN/无穷）以及角色互不重叠等已建立的不变量。
- 同一构建环境内要求精确复现；跨平台浮点位级一致性不属于本题保证。

## 验收场景

- 相同种子、配置和命令记录运行两次，得到相同终态。
- 回放命令记录得到与原运行相同的终态。
- 改变命令记录中明确规定可以调整的命令后，模拟结果按预期改变。
- 在一组小型多角色场景中，每个 tick 后的空间和身份不变量都成立。
- 重放不需要保存每帧完整世界；初始配置与命令记录足以复现结果。

## 思考

为什么固定步长、明确随机种子和稳定的冲突规则缺一不可？回放失败时，记录每个 tick 的状态摘要能怎样缩小排查范围？

## 可选拓展

加入世界快照的序列化和加载：比较“从头回放到第 N tick”与“加载第 K tick 快照后继续到 N tick”的结果。先定义哪些数据是权威状态、哪些（如空间索引）可以重建，再选择序列化格式。
