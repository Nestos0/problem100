# Problem 07 — 从同一世界快照推进所有角色

## 目标

构造全局模拟的一次推进：角色都根据同一份旧世界状态决策，不能因为容器遍历顺序不同而看到不同的新状态。

## 问题

实现 `stepWorld` 的第一版，按以下概念阶段推进：

1. 从当前 `World` 创建只读 `WorldView`。
2. 为所有角色计算 `Intent`。
3. 根据同一份旧状态计算所有移动提案。
4. 将提案写入新世界并推进 tick。

可使用 `Map` 保存角色，但规划阶段不能一边计算一边修改供其他角色读取的世界。

## 约束

- 所有决策读取同一个 tick 开始时的快照。
- 计算意图和提案阶段不修改输入世界。
- 更新结果写入新的世界状态。
- 本题暂不处理提案之间的碰撞；下一题会定义冲突规则。

## 验收场景

- `stepWorld` 不改变传入的旧 `World`。
- 所有角色恰好获得一次决策和一次提案。
- 以正序或逆序枚举角色来计算，得到的 ID 到提案映射相同。
- 新世界 tick 增加一次；角色身份与数量保持不变。
- 若决策读取其他角色位置，读取到的是 tick 开始时的位置，不是先更新角色的结果。

## 思考

如果角色 A 先被移动，再让角色 B 根据“附近角色”决策，遍历顺序会如何影响模拟？纯函数和快照分别解决了问题的哪一部分？

## 可选拓展

让所有角色同时观察并跟随同一个目标，测试交换角色存储顺序不会改变结果。
